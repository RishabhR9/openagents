# Backend tests that are known to fail.
#
# The Workspace backend inherited a set of failing tests. A CI gate that ran
# pytest plainly would therefore be red forever and would teach everyone to
# ignore it. scripts/ci/check_known_failures.py reports the entries below
# separately (in the job summary) and fails the job only for failures that
# are NOT listed here — so a newly broken test still blocks a pull request.
#
# Captured on Windows, Python 3.11, SQLite (no TEST_DATABASE_URL), with the
# SDK installed via `pip install -e ".[sdk]"`. The backend CI job runs on
# windows-latest for the same reason. When the job moves to another platform,
# re-capture this list:
#
#   PYTHONPATH=workspace/backend;sdk/src python -m pytest workspace/backend/tests/ \
#       -q --tb=no -rfE | tee pytest-summary.txt
#   python scripts/ci/check_known_failures.py --summary pytest-summary.txt \
#       --known scripts/ci/known_test_failures.txt
#
# Node ids are the ones pytest prints when it is run from the repository root.
# Remove an entry as soon as its test passes again: the checker reports
# recorded failures that now pass, so a stale list does not hide a real fix.
